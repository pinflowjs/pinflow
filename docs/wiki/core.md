# Core engine

The Pinflow core engine (`src/core/`) is a framework-agnostic annotation layer that wires together gesture input, element anchoring, localStorage persistence, and UI rendering. It powers both reviewer (single-user pin collection) and builder (chrome-less aggregate export) modes via a singleton lifecycle pattern initiated by `src/core/index.ts` `init()`.

## Module map

**`index.ts`** — Public entry point. Exports `init(config)` → `Handle`, `destroy()`, `routeOf()`, `version`, all types, and the artifact toolkit re-exports from `export.ts`. Delegates initialization and the page-wide singleton lifecycle to `runtime.ts`: resolves reviewer identity, acquires storage, creates the `Annotator`, and sets up route watching. The `Handle` contract (`destroy()`, `refreshRoute()`, `exportJSON()`, `exportMarkdown()`, `downloadExport()`) lets hosts control lifecycle, refresh pins when the logical screen changes without a URL change (frame-per-screen SPAs), and place their own submission moment.

**`types.ts`** — Shared data models and config. Defines `Comment` (the core entity with anchor, modality, metadata, and the server-owned `status`/`resolution` disposition), `ReviewerStore` (per-reviewer corpus), `Anchor` (selectors + fingerprint + position + optional marquee `areaPercent` rect + optional `covers` labels + optional pin-time `context` with accessible name/role/heading, image `src`, and a computed-style micro-snapshot), and `PinflowConfig` (project namespace, sync hooks `onChange`/`source`, optional voice config, theme tokens, `describeRoute`). Mode is `'reviewer'` (single user) or `'builder'` (an aggregate export switch since 0.9.0 removed the drawer UI: no chrome of its own — `exportMarkdown()`/`exportJSON()`/`downloadExport()` span every reviewer store in the browser).

**`ui/capture-annotator.ts`** — The shared capture state machine: pin creation (point + marquee area), editing, deletion, source hydration, and reflow. Private `_*` members are mangled by the build. Core methods: `_placeCommentAt()` (gesture→pin; resolves scope, picks the anchor, measures `areaPercent`), `_placeAreaComment()` (marquee rect → tightest containing element), `_renderPins()` (full rebuild), `_repositionPins()` (scroll/resize only), `_ensureIdentity()` (stealth deferred identity), `_openInput()` (explicit-save text editor; resolved comments open as a frozen read-only view with a muted disposition line), `_startVoiceDot()` (voice recording with generation guard), `_hydrateFromSource()` (fetch `config.source` once at identity resolution, guarded by a per-fetch token so a later hydration supersedes an earlier one and a display-name change does NOT cancel one in flight, merge, and re-announce local-only/locally-newer comments through `onChange`). Dispositioned pins render muted (theme `textMuted`): done swaps the number for ✓, declined keeps the number struck through; orphaned pins are hidden (the export sheet reports `· n unanchored`; bounded retries un-hide on heal).

**`ui/annotator.ts`** — Full widget subclass. It owns the export chip, sheet/confirmation, reviewer naming, revision-scoped clear, synchronous export methods and native sharing. It implements the base class's abstract handoff seams and adds the export hotkey after `super()`. The chip itself lives on the base class: `_syncChip` runs inside the base constructor, before this subclass's field initializers, which would otherwise reset it.

**`runtime.ts`** — Shared boot, route watcher and page-wide active handle. `initialize(config, Controller, api, inert)` constructs the entry's controller class and spreads its entry-specific methods over the lifecycle; `inert` is the complete handle for SSR and declined-identity installs. The stable public lifecycle occupies a symbol-keyed page slot shared by ESM/CJS/IIFE builds; internal mangled fields never cross that slot. The capture entry adds `getSnapshot()` in its own concrete controller so the full bundle does not retain snapshot-only code.

Anytime export ("summon, don't station"): `_syncChip()` — called from `_renderPins()`, the single funnel for every count-changing path — maintains the count chip (`button.chip`, docked bottom-left beside the arm segment, pin visual vocabulary) whenever the reviewer has comments and `_exportUiEnabled()` passes — reviewer mode only; builder mode has no chip since the 0.9.0 drawer removal (`exportUi` config: `'auto'` default is off when `source` is set). `_toggleSheet()` summons an anchored export sheet (`_makePanel` reuse; a summon unconditionally `_closePanel()`s whatever surface was up, and `_sheetOpen` marks the sheet so `_syncChip()`'s zero-count close never takes a confirmation down with it), saving any open draft losslessly first (`ActiveInput.save`), and no-ops when nothing remains to export. The sheet carries Export & share, a two-tap `Clear comments` beside it, and — when `onSubmit` is configured — Send to builder. It does not fork on disposal: `Export & clear` was removed in 0.11.0 because it asked for the wipe before either channel had run, and `download()` cannot report failure; 0.12.0 put a clear back on the sheet as its OWN control, never an export variant, whose armed line says plainly that nothing is exported first. The sheet and the confirmation attach the same machinery, `_attachClear()`: resting, a real bordered button in the shared `.panel button` box (0.12.1 — as quiet caption text it was not read as an action); the first tap hides the panel's primary (Export & share / Done), shows a `Keep` button, and turns the control into the filled destructive `Clear N comments` (`.clr.a`) in the primary's place — a question with two answers, replacing the 0.11.0 `Clear N comments?` label that reviewers answered by pressing the accented Done beside it. `Keep` disarms and returns focus to the resting control. `batch` is read at the arming tap, after the fold — the confirmation returns the revisions the export froze, the sheet snapshots the corpus as it stands (a sheet wipe that empties the corpus closes the sheet through `_syncChip()`) — and the wipe is REVISION-SCOPED: the export freezes the artifact's `(id, revision)` keys (`_rev()`: a JSON tuple of `updatedAt`, the server-owned `status`/`resolution` (status canonicalized to `open` exactly as the exporter prints absence), `text`, `route`, `createdAt`, and `feedback` — authored content the artifact prints; tie-timestamp divergences between any two copies are tracked in `_foldConflicts` — recorded by `_trackTies()`/`_unionTracked()` before ANY union (fold, adoption, parked destination, rename) picks a tie winner, pruned only when the comment moves past the tie or leaves the board — and excluded from every clear; the silent local heal ladder is derived-data maintenance outside the stamp) in the same synchronous block that builds the file, and both taps fold the durable truth first (`_foldDurable()`: identity, then a disk union under the current key, rendering only on material change). `_clearReviewerComments(rev)` verifies before it reports: the strip is revision-scoped on every retry, the final memory+disk state decides `clean`, deletes are emitted only for ids with no surviving copy anywhere, and the wipe refuses while a `source()` hydration is in flight or after one has failed (`_hydrated` gates it: PROTOCOL deletes are id-keyed, and a backend revision this device never saw must not be destroyed). Arming attaches an outside-dismiss and a focusout listener, so leaving the panel by tap or by keyboard disarms; the armed composite disposer CHAINS whatever the `_sheetDismiss` slot already held (the sheet's own outside-dismiss) rather than replacing it, so `_closePanel` still disposes both and a mere disarm hands the sheet's back untouched — feedback added or edited after the export is not in the file, so the clear never takes it, and when nothing of the batch remains the control retires instead of arming — at the confirming tap too, where an emptied batch reports "Nothing left to clear." rather than success. A second activation inside the ~600 ms arming window is swallowed (one gesture is never both taps), a held Enter is `repeat`-guarded, clicking any other panel control disarms, and both retirement paths park focus on the primary (or on the arm segment when the sheet has already closed under them). Clearing deliberately leaves the panel open with both retries live — they re-send the held artifact, so they outlive the store they came from; `_say()`'s write generation keeps a slow re-copy from overwriting the armed warning. An open sheet's title tracks the corpus live. The popup's `Export all · n` action and the `⌘/Ctrl+Shift+E` chord (registered at construction, removed on destroy, `repeat`-guarded) route through the same `_toggleSheet()`. `_positionPanel()` anchors to whatever summoned the panel and falls back (chip, then arm segment, then the dock's home corner) if the anchor left the DOM mid-flight.

Armed-mode direct manipulation (0.5.0 — the reviewer menu panel AND the bottom-right control are GONE; one bottom-left `.dock` holds the arm segment (`.arm`: `+` arms, `×` stops, accent while armed — `_renderDock()`/`_syncArm()`) plus the count chip, and the page itself is the interface): while armed, `_onHoverMove` — a capture-phase passive `pointermove` listener attached in `_enterAnnotateMode` and detached in `_exitAnnotateMode` alongside `pointerdown`/`pointerup`/`pointercancel` (zero armed-listener work at rest, mirroring the gesture controller's press-scoped pattern) — rAF-throttles `_paintHover()`, which boxes the CANONICAL anchor target under the cursor (`anchorTarget()` — preview = what a click stores) with a non-interactive `.hl` outline (accent border + faint accent wash, `pointer-events:none`) rendered inside the shadow root from `getBoundingClientRect` — host element styles/classes are never touched. Pinflow's own UI is skipped via `_isOwnUi` (the shared composedPath guard, also used by `_onDocumentClick`), and `_clearHover()` removes the outline and cancels any pending frame on disarm/pin placement/Escape.

Footprints: every visible comment renders a `.area` marching-ants region beside its pin (four 1px `repeating-linear-gradient` edges in `currentColor` + faint wash, `pointer-events:none`, ants frozen under `prefers-reduced-motion`). Drawn areas show the drawn rect via the shared `_areaRect()` (anchored element's live rect × `areaPercent`, compound-clamped, 2px-floored, inward-shifted at edges); element-anchored point comments show the CAPTURED element's live bounds, except degenerate anchors (collapsed or near-viewport boxes like `<body>`), which stay hidden. Created in `_renderPins`, repositioned in `_repositionPins` via `_placeArea()`, muted via `[data-status]`, hidden with orphaned pins. Area pins STRADDLE the footprint's top-left corner (Figma-style, derived at render from the same `_areaRect()` so pin and footprint can never drift; `positionPercent` keeps recording the drawn center as provenance).

Drag-to-marquee (area picker): while armed, a mouse/pen press that travels past `MOVE_THRESHOLD_PX` becomes a marquee — the same `.hl` element flips to `[data-marquee]`, which dims the rest of the page with a single giant `box-shadow` spread (no overlay element) and drops the hover transition. On release, `_placeAreaComment()` resolves the TIGHTEST element whose box contains the drawn rect (`elementFromPoint` at the center, then ancestor climb; `document.body` fallback) and places a NORMAL element-anchored comment via `_placeCommentAt()` — pin straddling the footprint's top-left corner — carrying the rect as `anchor.areaPercent` `{x,y,w,h}` percentages of the ANCHORED element (clamped 0–100 by `areaWithin()`, which lives on the commit path beside the anchor it measures against so the two cannot describe different boxes). Persistence, healing, orphan handling, and rendering are identical to point comments; the voice path composes (an area + voice comment carries both). The drag's trailing `click` is swallowed exactly once (`once` capture listener, 0-timeout self-clear) so neither pinflow nor the host sees it. Sub-threshold presses stay plain clicks (point pin); touch drags never start a marquee — the passive listener can't `preventDefault`, so native scrolling wins. Escape or `pointercancel` mid-drag aborts without placing anything.

A rect spanning sibling elements has no tight common ancestor, so that climb lands on a page-level container whose first 80 characters describe a different screen entirely — which is what the export used to quote. The climb records the element each sample LANDED on and samples three points — the centre first, so `subjects[0]` shares `positionPercent`'s provenance, then the 1/6 and 5/6 diagonal insets — recording up to 3 deduped labels in `anchor.covers` (`getTextFingerprint` ≤40 chars, or the tag name for a text-less block; pinflow's own host is skipped). A sample whose own element already contains the rect records nothing, rather than naming its own container.

Recording the climb's LAST element instead — the highest child below the containing ancestor — was the 0.8.x behaviour and its own bug: a rect drawn slightly wider than the block it sits on walked past that block and quoted a sibling's opening text, while `positionPercent` still pointed at the right place. Nothing in the artifact could reveal the disagreement, so an agent reading the prose fields edited the wrong element. The anchor and `areaPercent` are unchanged by any of this: the centre climb reproduces 0.6.0 exactly, and a regression test pins that. Samples run once on `pointerup`, never on the per-frame reflow path. A hit is CLAMPED up past text-level tags to the nearest block, and deduped on the clamped element — two samples landing on different words of one paragraph are one subject. Without it a sample landing mid-sentence quoted an inline fragment, which on a page about feedback reads like reviewer prose inside the artifact. Known limitation: a diagonal still misses the anti-diagonal members of a 2×2 grid.

**A marquee's ANCHOR comes from the walk, not the containment climb.** The containing element is a ceiling, and containment is a cliff with no tolerance: a rect aimed at a small badge but drawn a few pixels past its section's seam finds nothing below the page shell, because nothing smaller holds both the badge and the sliver of the next section. The boundary escalating there is defensible — a loose draw earns a loose ceiling. The anchor following it was not. `buildAnchor` received that container, so `Element`, `Context`, `Computed`, all three selector candidates and `Position` described a page-level `<div>` the reviewer never pointed at, and `areaPercent` was measured against it — reporting a badge-sized rect as a few percent of the shell. Each field was accurate about the container and useless about the note, and the artifact printed six of them ahead of `**Change:**`, which still named the badge.

The region walk has no such failure mode: coverage is scored per element against its OWN area, so the badge scores as the sole member in the tight draw and the overhanging one alike. So `_placeCommentAt()` resolves scope FIRST and, when the walk was COMPLETE and `scoped.elements.members` holds exactly ONE element, anchors to that member — selectors, fingerprint, context, `positionPercent` and `areaPercent` all describe it (clamping to full coverage when the rect engulfs it, which is the honest reading). A region covering SEVERAL members keeps the container: a set has no single subject and the common ancestor is the honest answer for one. The BOUNDARY is never re-derived on either path — it answers "how far may a fix reach", which an overhanging draw makes loose, not wrong.

**Two corrections landed in 0.11.2, both consequences of that re-anchor.** `areaWithin()` clamps BOTH endpoints and derives the extent from their difference; deriving width from the raw drawn width clamped the right edge correctly and the left edge not at all, storing full coverage for a half-covered element. That was unreachable while the anchor was the containing ancestor — containment forbids overflow — and became routine once the anchor could be a member the rect spills past. And the sole-member rule is gated on `ScopeResult.elements.membersComplete`, which reports the `NODE_CAP` overrun specifically: `visit()` abandons the walk on the node budget, so one member found before it ran out is not proof one is all there was. The record's own `truncated` is the WRONG gate — `MEMBER_CAP` and `EXCLUDED_CAP` set it too, and the excluded case leaves `members` complete, so gating on it would drop the fix on any region grazing more than twelve elements. `membersComplete` lives on the non-persisted half of the result, so it needs no schema version and can never be read back from untrusted input.

Outside-dismiss of the draft popup and the export sheet (shared `_armOutsideDismiss`, which takes a thunk of exempt containers — the surface itself plus the chip, whose taps must reach their own handlers) requires a COMPLETED single-finger tap: armed on `pointerdown`, fired on the matching `pointerup`, aborted by a second pointer (pinch — including one landing on the popup), `pointercancel` (browser took the gesture: touch scroll, pinch-zoom), or release back inside the popup. The draft textarea is 16px on coarse pointers so iOS Safari never auto-zooms on focus.

**`ui/styles.ts`** — Three rule blocks: `dock`, `handoff`, `overlay`. `CAPTURE_STYLES` is dock + overlay; full `STYLES` splices the handoff block between them, so the full widget pays two runtime concatenations. The handoff block's position is load-bearing: `.chip` must follow the shared `.arm,.chip` rule and precede the reduced-motion and small-screen overrides, and the `.panel button` box must precede the coarse-pointer 44px rule. The armed clear is `.root .panel .clr.a` so it outranks the overlay block's later `.panel .clr:hover`. Inline CSS is hand-minified for the shadow tree. Defines `.root`, `.dock`/`.arm` (bottom-left dock: arm segment + chip share one circle rule), `.pin` (numbered badge), `.hl` (armed-mode hover outline; `[data-marquee]` adds the page-dimming box-shadow; transition dropped under `prefers-reduced-motion`), `.area` (marching-ants footprint for placed area comments), `.panel` (export sheet / confirmation), `.input` (text editor popup). `.root` also carries the touch-chrome suppressions every control relies on — `user-select:none`, `-webkit-touch-callout:none` and `-webkit-tap-highlight-color:transparent` (Chromium's translucent blue tap square) — which reach the controls by inheritance, so a control appended outside `.root` loses them; the host's inline `all:initial` resets inherited properties, so a host page cannot supply them. Theme tokens are CSS variables (`--pf-*`) consumed with fallbacks; media queries handle dark mode and mobile.

**`ui/dom-base.ts`** — Stylesheet-independent `createRoot(styles, strategy)` builds the isolated DOM tree and appends to `body` once ready. It provides `el()` and the geometry helpers. `syncLayer()` writes the visible area into `--pf-ox`/`--pf-oy`/`--pf-oh` on every sync, in the same `cssText` write as the dialog transform. `ui/dom.ts` preserves the internal `createUIRoot()` facade with full styles.

**Dialog layer (0.12.0):** `buildAnchor()` records `anchor.layer = { role: 'dialog', name? }` when the original target has a `[role="dialog"]` / `[role="alertdialog"]` / `[aria-modal="true"]` / open `<dialog>` ancestor (`LAYER` in `target.ts`), named by `layerName()`: aria-label, then aria-labelledby (resolved and joined), then the dialog's first heading, capped at 80. `resolveAnchor()` is layer-aware: with a layer it runs `findByCandidates()` scoped to each open dialog of the recorded name (any name when none was recorded) and accepts a hit only if that dialog CONTAINS it — an absolute xpath ignores its context node and a css path matches document-wide, so either can land on the page underneath — and returns null otherwise. A layer pin therefore parks (orphaned, hidden) when its dialog closes and never heals onto `main`/`header`/an nth-of-type sibling in the next modal; it snaps back when a dialog of that name reopens. `hasValidAnchor()` validates the layer strictly (`validLayer()`: role `dialog`, optional name ≤80). The annotator adds a `MutationObserver` on `document.body` (`childList`, `subtree`, routed through the rAF-throttled `_onReflow`) so the park/unpark happens on the host's own re-render rather than on the reviewer's next scroll; `_cachedAnchor()` re-resolves a disconnected element immediately; parked entries stay behind the 500 ms `_orphanRetryAt` gate, but a pass that skips them because of the gate schedules ONE deferred `_onReflow` (`_orphanTimer`, never stacked, cleared on destroy) for when the gate expires — a dialog reopening 100 ms after it closed used to stay parked until the next unrelated reflow. Export prints `**Layer:** dialog ‘name’` after Context in the anchored block and `**Layer:** dialog ‘name’ (parked)` in the orphan block — parked, not "closed": resolve returns null both for a closed dialog and for an open one whose contents changed, and the export cannot tell which (`layerLine()` in `export.ts`).

**`storage.ts`** — Persistence with schema versioning (`SCHEMA_VERSION = 4`; v1→v2→v3→v4 migration on load). Stores per-reviewer corpora under `pinflow:c:<encodeURIComponent(project)>:<encodeURIComponent(reviewer)>` — components are URI-encoded so colon-bearing names can't alias another namespace; a legacy raw-key read fallback keeps pre-encoding corpora (see `KEY_PREFIX`). Exports `loadStore()`, `saveStore()` (guarded boolean result, never throws), `loadAllStores()`, `upsertComment()`, `deleteComment()`, `emptyStore()`, and `mergeComments()` (id-match merge used by source hydration: higher `updatedAt` wins content, incoming server value always wins `status`/`resolution` — including clearing them). Migration coerces v1 records (defaulting modality to `'text'`), validates anchors DEEPLY (finite positionPercent/viewport numbers — no NaN% exports), and drops malformed entries; `normalizeComments` is exported and applied to `source` hydration payloads too; v3 added the optional disposition fields, so v2 stores need no field rewrite.

**`safe-storage.ts`** — Fallback to an in-memory `Map`-backed Storage shim when real localStorage is blocked (third-party embeds, sandboxed iframes, private browsing). `acquireStorage()` runs a WRITE probe (set+remove of a probe key) — Safari-private read-only stores get the shim up front instead of silently losing every comment; failures return `memoryStorage()` (non-persistent for the session).

**`anchor.ts`** — Element-to-pin anchoring. `buildAnchor()` uses `anchorTarget()` to prefer an actionable control, otherwise the nearest non-empty test ID without crossing a modal/structural boundary (the raw target is the fallback) so nested labels/icons inside an anchored control never lose the host's test-id contract, then captures selectors + fingerprint + click-to-percentage offset — all measured on that anchored element, plus the pin-time `context`: accessible name (via the shared `accessibleName()` ladder — aria-label, aria-labelledby, an associated `<label>`, alt, title — then the fingerprint; role via `roleOf()`; image `alt` included, capped at 80), role, nearest heading, truncated image `src`, and a computed-style micro-snapshot of what feedback is usually about (background, color, font, radius; defaults omitted). `resolveAnchor()` re-finds the element on re-render via the selector ladder. `anchorToScreen()` converts percentage offsets back to viewport coords. `currentViewport()` records dimensions for orphan fallback.

**`selector.ts`** — Selector generation and resolution. `buildSelectors()` produces `SelectorCandidates` (testid, id, css, xpath, and — when `accessibleName()` finds one — `role` + `name`). `accessibleName()` is the shared ladder: aria-label → aria-labelledby (every id, joined) → associated `<label>` (`for=`, then wrapping) → alt → title, whitespace-collapsed and capped at 80; never text content, since the fingerprint owns text. `roleOf()` is the explicit `role`, else a small implicit map (`input` by type → checkbox/radio/slider/button/textbox, `a[href]` → link, button/select/textarea/img/dialog), else the tag. `buildAnchor()`'s context uses the same two functions, so the Context line and the locator cannot disagree, and `layerName()` (dialog naming) reuses `accessibleName()` before its first-heading fallback. The CSS path uses `nth-of-type()` and filters framework-generated IDs (React `useId`, Radix, auto-hashed tokens). `getTextFingerprint()` returns the first 80 chars, whitespace-collapsed; it normalises a bounded prefix rather than the whole subtree, falling back to the full string when whitespace-heavy markup makes the prefix yield under 80 characters — so the value is identical to a full normalisation while the cost stops scaling with subtree size.

`findByCandidates()` implements the ladder (testid → id → role + name → CSS → XPath → fingerprint walk). The role + name rung (`findByName()`) queries `[role=X]` plus the role's implicit tags (`ROLE_TAGS`, deliberately loose — `roleOf()` filters per candidate), compares `accessibleName()` per candidate under the shared deadline, and collects at most two: a complete single match wins; two means ambiguous and contributes no positional corroboration. Exhausting the deadline is incomplete, never proof of uniqueness. Testid and ID rungs also require uniqueness. Three properties matter more than the order:

- **Positional rungs do not outrank contradicting content.** A CSS/XPath hit whose fingerprint contradicts a stored one of at least `FUZZY_MIN_FP` characters is _demoted_, not discarded — and an EMPTY candidate fingerprint counts as contradiction, not confirmation (0.4.1 review #2): the pinned element provably had text, so a blank node at that path is a recycled or still-loading stranger. Without this, recycled nodes in a virtualised list keep satisfying a stale `nth-of-type` and silently reattach a comment to different content.
- **Resolution prefers a unique exact match, then positional evidence, then an untied fuzzy match.** A demoted positional hit still outranks a fuzzy candidate: css/xpath agreement is structural evidence, a 0.6 Dice score is a guess, and `_persistHeal` writes whatever wins back into `anchor.selectors` — so a wrong choice here is permanent, not transient. Only an _exact_ fingerprint match displaces a positional hit — and layout eligibility gates exact-match ACCEPTANCE itself (0.4.1 review #3): zero-box elements are skipped in the walk, a visible wrapper that merely mirrors a hidden carrier's text is dropped, and a later visible duplicate (or an honest orphan) wins, so a hidden stranger's selectors can never be persisted as a heal.
  **Documented residual:** a _visible_ stale duplicate of the old text is an exact match and wins. That case is not decidable from the DOM alone.
- **The walk starts at `<body>`,** skipping tags that can never be a pin target (`SKIP_TAG_RE`, matched against an uppercased `tagName` so SVG and XHTML are covered). Scoring `<head>` let `<title>` win as an exact fingerprint match that the deepest-wins rule could never displace, because that rule only replaces a match with its own descendant.
- **Ties abstain; truncation only drops the fuzzy guess.** Matching ancestors/descendants collapse to the deepest element; equal matches on distinct branches are ambiguous (an exact tie falls back to positional evidence, a fuzzy tie abstains). A walk cut short by `FINGERPRINT_WALK_LIMIT`/`FINGERPRINT_VISIT_LIMIT`/`FINGERPRINT_WALK_MS` still returns an untied exact match — most real pages exceed the budget, so requiring a complete scan disabled this rung where it matters — but never a partial fuzzy result, which an unscanned node could beat.
- **Three bounds, whichever trips first.** Two counters, because one cannot do both jobs: `FINGERPRINT_VISIT_LIMIT` (20000, charged by _every_ node) bounds work, so a `<select>` of thousands of `<option>`s cannot outrun the walk; `FINGERPRINT_WALK_LIMIT` (2000, charged only by _scored_ nodes) bounds meaning, so a gallery's 1,500 `<source>` elements cannot evict real content and push the heal onto the page container. `FINGERPRINT_WALK_MS` (2 ms, sampled every 16 visits) covers the device gap — 2000 nodes is roughly 1.5 ms on a laptop and 9.5 ms on a mid-range phone. Per-node cost is bounded too (0.4.1 review #7): heal-time text extraction streams text nodes in 2 KB chunks via `healFingerprint()` against the same shared deadline (created before the positional rungs, so corroboration spends from the same budget) instead of materialising subtrees via `textContent` — which stays pin-creation-only. Hydrated fingerprints are capped to the 80-char representation (`FP_MAX`) at both the hydration (`normalizeComments`) and matcher (`findByCandidates`) boundaries before any O(length) work (review #8).

**`scope.ts`** — Region → element SET at one instant (`selector.ts` is one element ⇄ durable strings across renders; `anchor.ts` is one element → record at one instant). `resolveScope(target, region?)` returns the serializable `Scope` plus live element refs from ONE walk, so the outline can never disagree with what was stored. Top-down walk with early stop at the first `inside` node; recursion is driven by INTERSECTION not band, which is what makes the exclusion invariant structural (an ancestor of an emitted node always reports EMITTED and can never reach the exclusion branch). Coverage is `area(rect ∩ el)/area(el)` — coverage-of-target, clipped against the container first. `climb()` is the five-rung ladder (source → testid → repeated → landmark → anchor), exported for `anchor.ts` reuse; it records each level under its STRONGEST rung only, which leaves the winner unchanged because a weaker entry is read only when no stronger one exists. `demoteScope()` is what a heal leaves behind. **Zero `_`-prefixed identifiers, enforced by a source-reading test** — mangling is per entry point and skips quoted access, so a `_` key on a persisted record is silent data corruption CI cannot catch.

**R4's size check is split, and the halves are not interchangeable.** `tooManyDescendants()` is share-of-document-elements; `tooWide()` is that OR share-of-document-**area**. Point pins use `tooWide()` — their boundary comes from the ladder and can be a sparse hero the descendant test misses. **Marquees use `tooManyDescendants()` only**, because `containerFor` has already bounded their boundary to something containing the drawn rect.

Both corrections landed in 0.9.0 and both were the same mistake. The region branch skipped the check entirely, so a marquee resolving to the whole page published at `medium` while a tightly-scoped point pin published at `low`. And the area half divided by ONE VIEWPORT, which made it "is this element taller than the display" — true of almost every section on a content page, measured at 1.97 viewports for a `<section>` holding 18.7% of its document. That is what collapsed a correctly-resolved `repeated` boundary onto the pinned element and emitted no `**Change:**` block at all. R4 asks whether a candidate is really _the page_, and the page is the document: the denominator is `documentElement.scrollHeight` (falling back to the viewport height, which reads 0 before layout and in happy-dom).

**`siblings`** records the total same-tag children of the members' shared parent when the members are only some of them, so the export can say `2 of 5 <li>` rather than `2 element(s)`. A rect slicing one column of a grid produces three states — members, grazed exclusions, and untouched children recorded nowhere — of which the artifact renders two, so the counts otherwise read as a deliberate permission list over a set the reviewer meant whole. The members are deliberately NOT widened to the parent: that is the covered-set model's founding bug.

**The source hint resolves from an ancestor, then from a single descendant.** `climb(boundary)` supplies it rather than `sourceOf(boundary)`, because a marquee's boundary is picked by containment and is almost never a component root — reading the attribute off the boundary alone delivered a hint on roughly one note in five even on a fully instrumented page. A point pin whose boundary already carries the attribute finds itself first, so this is a superset of the old behaviour.

The climb is upward-only, which loses the hint whenever a layout wrapper sits **outside** the annotated component — `<div class="wrap"><Hero/></div>`, the shape the audited site uses for its hero and nothing else. That was the one note in a seven-note export with no hint while every other section resolved one. So when the climb finds nothing, `boundary.querySelectorAll('[data-pinflow-source]')` is consulted and used **only if it returns exactly one element**. Two candidates is a coin flip, and a hint naming the wrong file is worse than none because agents are told to confirm a hint rather than distrust it. The rung is never promoted by this path: an ancestor declares, a descendant only implies, and `rung` drives the boundary's own confidence.

**R9 — an empty member list is not automatically an insertion.** Coverage is scored against each element's OWN area, so a marquee small relative to everything it crosses clears neither the `INSIDE` (0.9) nor the `PARTIAL` (0.35) floor and leaves `members` empty. The insertion arm used to read that as "the reviewer drew a gap". On a real hero note it published an absent change list, the `<h1>` the note was about under **Do not change**, and an insertion point asserted inside a container holding three elements.

"Did it graze anything" cannot be the discriminator — a rect that clips 10px of a paragraph and sits 90% in the gap genuinely IS an insertion. `Walk.fill` measures the region from the other side: the largest slice of the **drawn region** any grazed element fills. When `fill >= PARTIAL * area(region)` the reviewer was drawing across content, so the grazed set is promoted to `members` and `excluded` is cleared; otherwise the insertion arm still runs. Promoted members carry the `partial` band (nothing cleared the floor) and confidence drops one step — the boundary claim is untouched, since a source rung still found what it found.

**Both caps announce themselves.** `MEMBER_CAP` and `EXCLUDED_CAP` now set `truncated` (which demotes confidence and renders), so a busy marquee cannot publish a twelve-item exclusion list that reads as the whole set.

**`source-path.ts`** — `validateSourcePath()`: positive charset, per-segment rejection, extension allowlist deliberately excluding `.md`/`.json`/`.yml`/`.sh`. Its own module because all three call sites need it and two (`export.ts`, `storage.ts`) must not import the engine.

**`scope-limits.ts`** — the record caps `scope.ts` applies at capture and `storage.ts` re-applies at hydration. One home because neither module may import the other.

**`ui/outline.ts`** — `ScopeOutline`: 2px + wash for a change target, 1px for the boundary, dashed for uncertain, a seam bar for an insertion. Exclusions are never drawn. Zero-area falls back to the `getClientRects()` union and then drops the box — a fabricated box is worse than an absent one.

**`router.ts`** — SPA route watching via `history.pushState`/`replaceState` patching plus popstate/hashchange listeners. `watchRoute()` emits onChange only when the route actually changed and guards against orphaned callbacks.

**`route-key.ts`** — Strips pinflow-internal URL params (`reviewer`, `mode`) before deriving the logical screen key, so comments anchor to the conceptual route.

**`export.ts`** — Artifact generation for reviewer and builder modes, re-exported from the package entry as a standalone toolkit. `exportReviewer()` groups comments by route with full selector detail; `exportBuilder()` adds reviewer names and a summary; `exportJSON()` emits the versioned machine-readable corpus. Headings carry the comment id and a disposition suffix; a host `describeRoute` turns `## Route: <key>` into a friendly title with the stable key in backticks beneath. Per-comment lines include **Context:** (accessible name/role/nearest heading), **Computed:** (pin-time style snapshot), **Image:** (truncated src), and **Resolution:** (team note) when present. Orphaned comments are segregated but KEEP their context/computed/image lines — the last-known visual state is exactly what remains when the target is unavailable. `exportFilename()` timestamps output (`pinflow-feedback-[reviewer-]project-timestamp.md`).

**`gesture/controller.ts`** — Stealth gesture recognizer. Touch/pen: a 400 ms long-press CLAIMS the gesture (0.5.x hold-then-drag — firing before the ~500 ms platform recognizer; a zero-size marquee dim is the cue, a non-passive `touchmove` locks the scroller out) and the RELEASE disambiguates: in place = point pin, dragged past the threshold = area commit. Pre-hold movement stays a native scroll, and without area callbacks the legacy timer-fire activation is unchanged. Every touch/pen press also holds the document-level selection guard (`ui/selection-guard.ts`, refcounted, constructed-sheet with `<style>` fallback) so WebKit's long-press text selection + Copy/Search callout can never fight the pin gesture — the annotator holds the same guard for all of armed mode. On desktop a primary-button Alt press resolves on RELEASE — still = point pin (`onActivate`), past the 10px threshold = area drag whose corners stream through `onAreaChange`/`onAreaCommit`/`onAreaCancel` into the annotator's marquee machinery (every area callback defers while armed, so the armed-mode press handlers can never double-fire). Alt with a non-primary button is ignored. Runs in capture phase with swallow-timing so host click handlers don't fire. Active only in `'stealth'`/`'both'` activation modes.

**`iife.ts`** — CDN auto-init shim. Reads `<script data-project="..." data-activation="...">` and calls `init()` after DOMContentLoaded.

## Data flow

**Gesture → pin creation:** click (or long-press via `GestureController`) → `_placeCommentAt()` → `buildAnchor()` resolves the containing action or bounded test-ID ancestor and captures candidates, fingerprint, viewport, percentage offset from it. With voice configured, `_startVoiceDot()` lazy-loads the voice module and starts a session; otherwise `_commitTextComment()` runs immediately with empty text and `openForEdit=true` to show the editor.

**Text input → persistence:** the `.input` popup saves on Save click or Cmd/Ctrl+Enter. Saving calls `upsertComment()` then `_persist()` → `saveStore()`. Comments without text are auto-deleted on dismiss unless they carry a saved expected outcome; `ActiveInput.fresh` marks a composer opened by the creating gesture, so host `captureContext` prefill alone never keeps a pin the reviewer dismissed unsaved (Save keeps a prefilled expected outcome). `onChange` fires after persist.

**Voice → persistence:** the voice module streams interim/final text and emits `commit(text, meta)` when done. `_buildVoiceHost()` supplies shared voice comment construction and a text fallback via `_commitTextComment()`, both with **frozen route, full URL, scope and feedback** (captured at dot creation, not commit time, to survive route changes mid-recording). Voice failures degrade to text via `degradeToText()`.

**Route change:** `watchRoute()` fires → `_generation` bumps → in-flight voice stops and persists to its frozen route → the open draft popup closes → `_renderPins()` clears both caches and renders pins for the new route.

**Source hydration (read half of PROTOCOL.md):** when reviewer identity resolves (init, or first stealth gesture), `config.source()` is fetched once (synchronous throws contained, payload normalized like localStorage) and merged via `mergeComments()`. The fetch is guarded by destruction/identity, NOT the route generation — SPA navigation mid-fetch keeps the corpus. A comment resolved by hydration while its editor is open discards the stale edit at Save. Local comments the server lacks — or has stale (`updatedAt` older than local) — are re-announced through `onChange` as add/update, so transient sync losses self-heal (reconcile-on-load). Hydration-applied changes themselves never emit `onChange` (echoing the host's own data back would loop). Rejection is a dev-visible warn; localStorage stays authoritative.

**Reflow (scroll/resize):** rAF-throttled `_repositionPins()` reuses cached anchors and moves existing pin elements only — no DOM churn. Scroll is observed at the DOCUMENT capture phase so nested overflow containers reposition pins too. Orphaned (null-cached) anchors retry the selector ladder at most every 500ms, so late-mounting elements heal without per-frame cost.

**Visibility filtering:** `_visibleComments()` filters by current route; reviewer mode shows only the current reviewer's comments; builder mode renders none (the aggregate lives in the handle's export methods, not on screen). Memoized; cache cleared on data mutation or route change.

## Annotator widget internals

**Shadow DOM structure** (host element carries `data-pinflow-root`): styles (see below), `.root` (fixed full-viewport, pointer-events:none), the `.dock` (arm segment + count chip), numbered `.pin` badges (position:fixed), `.panel`, `.input`, and a voice-dot mount.

**Stylesheet delivery is CSP-sensitive.** A shadow root has no CSP context of its own — the document policy governs the whole tree — and inserting a `<style>` element runs the inline-style check, so `style-src 'self'` without `'unsafe-inline'` drops it. That failure is not merely cosmetic: the host's `pointer-events:none` is set through CSSOM, which CSP does _not_ restrict, while every `pointer-events:auto` lives in the stylesheet, so the widget becomes an invisible and completely non-interactive overlay with no error. `createUIRoot()` therefore adopts a constructed `CSSStyleSheet` (CSSOM has no CSP hook) and keeps the `<style>` element as a fallback for engines below the constructed-stylesheet floor (Chrome 73 / Firefox 101 / Safari 16.4). `resolveStyleStrategy()` picks between them and also rejects an engine that accepts `replaceSync` while discarding the rules. The strategy is a `createUIRoot()` parameter so tests can drive both branches — happy-dom always takes one.

**Lifecycle:**

1. Base constructor: create shadow root, apply theme, load state, then render the dock/pins, start gestures/hydration and attach listeners.
2. `refreshRoute()`: bump generation, stop in-flight voice, close inputs, re-render pins.
3. `destroy()`: stop gesture, tear down voice, close inputs, remove listeners, clear shadow tree, set `_destroyed=true` so late async callbacks self-cancel.

**Rendering strategy:** `_renderPins()` fully rebuilds pin DOM (resolve each anchor, create badges, cache resolved elements); `_repositionPins()` only updates screen positions during reflow. A stale element that left the DOM is re-resolved once; orphaned entries are hidden between bounded retries; a heal through the fallback chain (fingerprint/fuzzy Dice ≥0.6 with same-tag bias) also persists rebuilt selectors silently (no onChange, no updatedAt bump).

**Theme application:** the constructor's `_applyTheme()` sets `--pf-*` custom properties on the shadow **host element**, and `styles.ts` consumes `--pf-font-family` on `.root` rather than `:host` (see the comment in `src/core/ui/styles.ts` for the browser quirk). All tokens optional; omission keeps the stock design.

**Generation guard / destroyed flag:** `_generation` increments on `refreshRoute()`/`destroy()`; in-flight voice loads check `myGen !== this._generation` and cancel. Late callbacks check `_destroyed` and no-op, preventing DOM writes and storage mutations after teardown.

## Identity

Nobody is asked who they are at page load. `resolveReviewer()` in `identity.ts` takes the first of: the `?reviewer=` URL param, a name remembered under `pinflow:r:<project>`, or — when the caller supplies a `mint` — a freshly minted `anonymousHandle()` (`anon_` + a `randomToken()` from `id.ts`, the same generator comment ids use). Non-stealth reviewer mode mints at init; **stealth passes no `mint`**, because it must leave no trace in storage on a page the reviewer never activated, and resolves on the first gesture instead.

A minted handle is a storage key, never a display name. `attribution()` in `export.ts` is the single rule that keeps it out of artifacts, and every public entry point applies it — `exportReviewer()` drops the `— from` and the `Reviewer:` line, `exportFilename()` drops the who segment, and single-store `exportJSON()` blanks the per-comment `reviewer`. The builder aggregate (`exportJSON` with an array) keeps raw handles on purpose, so two unnamed reviewers stay distinguishable. `isAnonymous()` matches the exact minted shape (`anon_` + nine chars), not the prefix, so a real reviewer called `anon_dave` keeps their attribution. (`exportFilename` distinguishes three cases: `null` is the builder aggregate, `''` is an unnamed reviewer, a string is a name.)

The export sheet carries the optional name field (`input.name`, prefilled from `_displayName()`, Enter exports). `_settleName()` runs before the artifact is built and is shared by BOTH terminal actions — Export & share and Send to builder — so `onSubmit` sees the same name the export does. It returns the export-scoped attribution: a typed name renames via `_renameTo()`; a **cleared** field is an opt-out that suppresses attribution for that artifact only, without renaming; no field at all defers to the stored identity. The built artifact is handed to the confirmation panel, whose retry buttons re-send it rather than rebuilding — a rebuild would re-derive attribution from storage after the field is gone.

`renameReviewer()` in `storage.ts` does the move, because the corpus key embeds the reviewer. Order is **copy → remember → delete**: the identity marker must land while the source still exists, so that if any single write fails the old name still resolves to an intact corpus. Duplicate ids are resolved by `unionByRecency()` (newest `updatedAt`, ties to the destination) rather than by id alone. A refused copy returns `false` and commits nothing.

**Cross-tab.** `persistence.ts` reconciles each tab's desired changes against its durable baseline and the latest disk snapshot. Unchanged stale records do not overwrite edits or revive deletions; distinct additions survive sequential writes. Ties favor durable state on conflict. Renames rebase onto the destination snapshot, preserving pending local deltas, and merged remote feedback refreshes pins/counts. Exports also fold durable state. This is lockless synchronous localStorage, not atomic cross-process transactions.

## Storage behavior

- **Schema:** `schemaVersion: 4` (`SCHEMA_VERSION` in `src/core/storage.ts`). v1 records (no modality) migrate on load with `modality='text'`; v3 added optional `status`/`resolution`, so v2 records pass through unchanged v4 adds `scope`, which validates SOFT: `validScope()` returns `undefined` for a malformed value so the comment survives without a scope, rather than the record being dropped.
- **Validation:** `normalizeComments()` drops entries with missing `id`, malformed `anchor`, or invalid selector shapes; coerces text/route/createdAt to strings. `textFingerprint` is validated STRICTLY as a string (not `optStr`): it is dereferenced for the `FP_MAX` cap a few lines later, so a null/absent value used to throw a `TypeError` that discarded the entire store rather than the one bad record. `covers` is validated as string-or-ABSENT (not `optStr`, which admits `null` and would preserve it into a field typed `string | undefined`), so old records validate unchanged and no `SCHEMA_VERSION` bump is needed; each label is re-capped to 40 chars at the export chokepoint, since a `source()` payload never passes through capture. `scope` is validated by `validScope()` (boundary node, finite `gen`, and `rung`/`confidence` from closed sets). `siblings` is admitted only alongside members, only when it is an integer strictly greater than the member count and under 1e4, and only when every member shares one tag — it renders into a sentence an agent acts on, so "2 of 2" says nothing, `1e21` would print as `1e+21`, and a mixed-tag payload would render "2 of 9 `<li>`" over a set containing a `<section>`. The tag condition mirrors capture, which sets the field only for members sharing one parent AND tag. Node strings are sanitised on the SAME terms as capture via `cleanLabel()` in `scope-limits.ts` — invisible/bidi/Unicode-tag stripping on `label` and `testid`, `tag`/`css` bounded by `TAG_MAX`/`CSS_MAX` and the node rejected rather than truncated. Capture reads the DOM; this boundary reads backends, imported exports and tampered blobs, and `exportJSON`/`onChange` carry these strings past the markdown escapers untouched.
- **Blocked access:** SecurityError on read → in-memory shim; comments last the session only; a single console.warn on first write failure.
- **Rename:** `renameReviewer()` moves a corpus between reviewer keys (copy → remember → delete), folding duplicates with `unionByRecency()`. The remembered identity write is read-verified before source deletion. A refused marker leaves the reachable source intact; a destination copy may remain.
- **Forward tolerance:** `migrate()` reads hypothetical v3+ stable core fields; foreign data (missing reviewer/project/schemaVersion) is discarded.

Reviewer export shape:

```
# Feedback for <project> — from <reviewer>
Generated: <timestamp>
[comment count, routes covered]
---
## <describeRoute label (stable key in backticks beneath), or `Route: /path`>
### Comment 1
**Comment ID:** `<comment id>`
**Status:** open|done|declined (always present; derived ONLY from the validated status value — 0.4.1 review #1)
**Reviewer:** <reviewer> (builder export only)
**Created:** <createdAt>
**Element:** <button data-testid="..."> ("fingerprint") — the tag falls back to the xpath's last step when the css path is id-only (`#main` carries none); a fingerprint that hit FP_MAX ends with an ellipsis
**Context:** the 'Continue' button under 'Next section' (on area comments the heading comes from the block under the rect, not the climbed container — only the heading; every other field still describes the anchored element)
**Computed:** background rgb(…), text rgb(…), font 17px DM Sans, radius 14px
**Image:** https://… (image pins only)
**Selector candidates:** testid / css / xpath as inline code
**Position:** X% from left, Y% from top of element
**Area:** W% × H% of the element, from X%, Y% (marquee comments only; numbers only)
**Area covers:** “label”, “label”, “label” (marquee comments that sampled blocks; split-then-escaped per item, capped at 3)
**Motion:** `<div>` (“label”) — `css` animates `props` — the nearest element at or above the change set that actually moves; a LEAD, often outside `members`
**Scope:** `<div>` — `css` (rung: …, confidence: …, gen: N[ — older tuning][, stale][, truncated]) — captured containment, not edit permission. `gen` is the tuning that WROTE the record: scope is stored, not re-derived at export, so an old comment renders its old boundary and the marker is the only thing that says so.
**Source hint (page-supplied, unverified):** `path` — resolved from the boundary OR any ancestor
**Selected — N element(s) observed at capture:** / **Selected — N of M `<tag>` observed at capture:** when the region sliced a repeated set
**Do not change — N element(s) the region only touched:** — what the rect GRAZED, for that note alone; the preamble gives a default (prefer leaving them; change one if a coherent fix needs it and say so) rather than a prohibition
**Insertion point:** between … and … (a region drawn over a gap)
**Viewport at time of comment:** 390×844 (mobile)
**Resolution:** <team note, when present>
> comment text, blockquoted
```

Builder export adds a summary table (total, by reviewer, by route) and reviewer names per comment. Orphaned comments get their own section with last-known selectors. **Every interpolated field is untrusted** — comment text (blockquote-continued incl. bare `\r`), reviewer names, routes, ids, selectors, resolutions, context, and `describeRoute` labels are all newline-collapsed and code-span-safe so no field can fabricate top-level markdown or instructions when the artifact is pasted into a coding agent. Never weaken this escaping.

**Two escapers, and only one decision.** There used to be a third (`code()`, adding backtick handling on top of `inline()`), applied per field — which meant every new line asked "which escaper does this one need?", and three consecutive review rounds found a field that answered it wrong. Backtick handling now lives in the baseline and the question is gone:

- **`inline()`** — the baseline for _every_ interpolated field. Collapses all newline forms, so nothing can fabricate a heading or section, and neutralises backticks, so nothing can open a code span that swallows the rest of the block. The only bypass is `comment.text`, via `quoted()`, because a human's prose should keep its backticks.
- **`attr()`** — `inline()` plus `"`, `<` and `>`. Guards all **five** interpolations in the element label: the css tag, the xpath tag fallback, the `data-testid="…"` / `id="…"` pair, and the `(“fingerprint”)` segment. Each of those can close the attribute and forge a sibling that an agent extracting `data-testid="([^"]*)"` would trust — and the non-global form of that regex returns the _forged_ one first. The tag matters even though `cssSegment()` cannot produce a hostile one: `storage.ts` validates `selectors.css` as `typeof === 'string'` and nothing more, so a `source()` payload or an imported export supplies it freely.

The fingerprint's **typographic** quotes are load-bearing, not styling. With ASCII quotes that segment was the last free `"` on the line, so on the `id=` path the regex ran from the id's closing quote to the fingerprint's opening one and captured pinflow's own structure — harmless but a false positive an agent would then search for. They also make the fingerprint un-confusable with an attribute, which is the confusion that produced a finding in three consecutive review rounds.

`tests/core/export.test.ts` asserts the invariant **structurally**, against the source: every `${…}` in `export.ts` must route through `inline()`, `attr()` or `quoted()`. Three rounds of enumerating the fields someone remembered each missed one; this fails the moment an unescaped interpolation appears.

`selectorLines()` deliberately stays on the baseline — it is the only faithful copy of a selector value, and the agent pack directs searches there precisely because `attr()` substitutes characters in the label.

Escaping defends the artifact's **structure**, not its **meaning** — a perfectly-escaped accessible name can still read as an instruction. The reading protocol that names that boundary ships as markdown in `agent/` (see `build-and-release.md`), deliberately outside the bundle.

## Key internal conventions

- **`_` prefix = private + mangled** (tsup `/^_/`). Renaming `_` members changes minified output; treat as semantic.
- **Singleton:** symbol-keyed page-wide active handle in `runtime.ts`; `init()` during an active instance warns and destroys the old one.
- **`onChange`:** fires after every persisted add/update/delete; host exceptions caught and logged.
- **Deferred identity (stealth):** `_ensureIdentity()` mints on first pin attempt, not at init — stealth must leave no trace in storage on a page the reviewer never activated.

## Actionable capture evidence

`feedback.ts` owns an allowlist normalizer reused at capture and hydration: build/state, steps, observed/expected, acceptance and passive attachment references. Unknown keys are dropped, strings bounded, and arrays detached. `captureFeedback` contains host-hook errors. `captureUrl` applies an optional query allowlist to newly captured full URLs and default route keys; undefined preserves legacy behavior. It does not sanitize page text/styles/image URLs, custom route keys or historical records.

`buildAnchor` retains the raw clicked descendant as `anchor.target` when anchoring an ancestor. On first repair, `_persistHeal` saves `anchor.capturedSelectors`; `_healScope` retains `capturedScope` before demotion. Current selectors/scope retain their existing meanings. Repair writes batch once per pass, without `updatedAt` or `onChange`. Cached dialog targets must still satisfy `inAnchorLayer`; the mutation observer watches dialog visibility attributes as well as subtree changes, so mounted closed native dialogs park their pins.

`evidenceLines` renders both live and orphan feedback. Parked Markdown retains historical scope, membership and viewport alongside the JSON twin. Missing or closed targets are unresolved, not asserted deleted. New free-text evidence goes through `evidenceText` (neutralizes Markdown link/image brackets) and the existing `attr` escaper, with code spans preventing URL autolinks; it never emits active attachment links. Context fields render with sentence-case labels (`Build`, `State`, `Observed`, `Expected outcome`). The AST interpolation guard remains unchanged. Optional expected-outcome composition uses the existing save/discard lifecycle and persists substantive expected-only notes.

## Target integrity and capture diagnostics

`target.ts` captures bounded repeated-owner evidence (`tr`, `li`, `article`, ARIA
row/listitem), including owners across shadow boundaries, plus up to eight open shadow hosts. `owner.rootDepth` records which root contains an outer owner. A unique owner ID/test ID is
binding; otherwise the owner's entity text identifies it. That text excludes the
anchored control's own subtree (`owner.path`, a relative positional path queried
as `:scope >` CSS), so a fix to the pinned control's label keeps its row; a
control that is the row's only text stands in as its label. Lookalike owners
sharing that text resolve by position (`ordinal`/`count`, recorded only when
several exist) and park when the count changes: a filtered or grown set is the
case a positional locator gets silently wrong. The scan is capped at 500 same-tag
candidates, 8 ms at capture and 2 ms per resolve; past the cap or budget the
owner is `ambiguous`, a locator hint that constrains nothing, so a pin never
parks at placement (owners are then dropped; a shadow host falls back to the
ladder). Changed identity or entity text parks the note, including a connected
recycled row and a live timestamp beside the control. An empty shadow path
explicitly marks excessive nesting and remains unresolved. Legacy comments
without these fields retain the legacy selector behavior.

`anchorTarget` stops at an action (`ACTION` in `target.ts`: native controls,
`summary`, and button/link/tab/checkbox/radio/switch/option/menu-item roles)
before climbing to an outer test ID, and cannot cross a modal/structural boundary. Layer evidence comes from the original target.
`resolveAnchor` resolves host and owner constraints before the control ladder;
optional `TargetResolution` reports availability, matched rung and owner agreement.
It does not claim that a positional/fuzzy locator proves identity.

`capture.ts` captures at most 512 text characters, 64 text nodes and 12 fragment
rectangles, element/parent bounds, six layout values, and boolean control/ARIA
state. It reads no input values. `details.ts` normalizes/detaches these optional
facts for storage and export; malformed owner/host binding evidence keeps the
record but replaces its binding with an empty shadow path, which parks the note
until it is re-placed, so hydration neither widens the target nor drops words. Canvas/iframe/custom hosts
without an open root and without light-DOM children or text carry a surface
limitation; a custom element with its own children is an ordinary light-DOM
component. A closed root on a generic built-in element cannot be detected from
outside.

`ui/dom-base.ts` moves the overlay into the active native modal and restores it after
close, re-appending it on the next reflow if the host re-renders the dialog's
children. A dialog with a transform, filter or containment becomes the containing
block for the overlay's fixed boxes; a zero-size probe measures that offset and
`root` is translated back onto the viewport so pins land on page geometry. The
dialog's UA `overflow:auto` still clips to its box, so `bounds()` (and the
`--pf-ox/oy/oh` variables the dock reads) confine the dock, composer and export
panel to the intersection of the dialog's padding box and the visual viewport. The padding
box is measured from the dialog itself so scrolling its contents does not move the clipping bounds.
`bounds()` uses `visualViewport` dimensions and offsets, falling back to the layout viewport.
Visual viewport resize/scroll events schedule the same rAF reflow and are removed on destroy.
`fit()` constrains composer/panel dimensions before measurement; overflow scrolls internally. It keeps the stylesheet's width floors (240px composer, 260px panel) unless the visible area is narrower.
`flipPosition()` clamps both edges even when a pin is outside the visible viewport. The composer
synchronizes its layer before measuring and focuses with `preventScroll`. Status writes also
reposition the export panel after text wrapping changes its height. Composer Escape consumes native cancellation. The mutation observer also
observes the open shadow roots of resolved targets, and caches recheck owner
agreement before reuse. All selector repair paths call `_persistHeal`.

The composer offers an optional `feedback.intent` selection. `captureContext`
receives `{clientX, clientY}` and may return a bounded `subject` for host hit tests.
Exports label host/reviewer context as unverified. Scope confidence describes
historical containment; membership does not declare which instances to edit.
Handle exports report current target diagnostics only on the active route; other
routes are `not-checked`. JSON keeps them in top-level `targetResolution`, outside
persisted comments and revision hashes. DOM-free toolkit callers can supply a
resolver; without one Markdown says `not-checked` and JSON omits diagnostics.

### Mobile export delivery

`_touch()` (`any-pointer:coarse`) identifies touch devices, including tablets with a fine
primary pointer; it also switches the export sheet's body copy from the download promise to sharing.
On touch, `_handleReviewerExport()` freezes the artifact/revision batch and opens the confirmation
synchronously, invoking `shareFeedback()` before leaving the tap activation. There is no automatic
download or clipboard write on this path. `download.ts` probes Markdown-file support, then a
plain-text attachment, then sends the complete text through `navigator.share`. Cancellation and
unsupported/blocked sharing keep the comments and offer retry/copy; only a refused share
(`unavailable`) changes the status line. `_reCopy()` shows a selectable read-only copy of the
artifact whenever the clipboard write fails, on any device. Retries retain the original artifact after
clearing; pending share disables duplicate activation, and panel/generation checks suppress late
status writes. Sharing never claims recipient delivery; destructive warnings name the clipboard
copy only after a successful write. Desktop export and the explicit `downloadExport()` API retain
the download-and-copy contract.
